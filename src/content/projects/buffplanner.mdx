## A Hackathon in 24 Hours
 
A few weeks before [HackCU](https://hackcu.org/) this past March, I was trying to map out my class schedule for next semester. I had a Google Sheet with my four-year plan, and every time I moved a course I had no idea if I'd just broken a prerequisite chain or dropped something my major required. It was tedious enough that I kept thinking about what a better tool would look like. So when the hackathon came around, I built one.
 
BuffPlanner is a drag-and-drop four-year course planner. You can arrange courses across semesters, see your progress toward graduation requirements at a glance, and get flagged when something's missing a prerequisite or corequisite.

## How It Works
 
The frontend is React; the backend is a FastAPI service that handles data queries and logic against a JSON course database. Courses are draggable between semester slots on the frontend, and on each change the backend checks the current plan against prerequisite and corequisite rules and returns any conflicts.
 
My role was primarily the backend — API design, data modeling, and the prerequisite checking logic. My partner [Michael Santillan](https://github.com/PLACEHOLDER) handled most of the frontend and UI.

The most interesting technical piece was prerequisite checking. Prerequisites aren't just "you need class A before class B" — they're often nested conditionals. A course might require all of one set and any one of another: `MATH 2400 AND (APPM 2360 OR MATH 2130)`. I built a small evaluator that parses these AND/OR trees from the course data and checks them against whatever's in the student's current plan. Getting the logic to handle arbitrary nesting correctly, rather than just flat lists, was the part that took the most thought.
 
## 24 Hours
 
We started at the hackathon kickoff and submitted 24 hours later. A lot of that time was figuring out how to scope the project — what was achievable vs. what we wanted to build. We ended up with a working MVP: the core drag-and-drop planner, requirement tracking, and prereq checking all functional. The UI is rough in places, and the data layer is a JSON file rather than a proper database, but everything works.
 
## What's Next
 
The MVP is real software, just unfinished. The most meaningful improvements would be:
 
- Pull course data directly from CU's catalog instead of a static JSON file
- Support any major, minor, or certificate program (right now it's hardcoded to a specific plan)
- Persistent storage so your plan saves between sessions
- Mobile-friendly layout
- Advising tools for multi-user collaboration
Whether I'll get back to it, I'm not sure — but I think the core idea is genuinely useful, and the infrastructure is there to build on.
